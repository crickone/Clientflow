# OHR Ad Library — Next.js App

Faithful port of `OHR_HBOT_Ad_Library_Full_Report.html` into a Next.js 14 App
Router project with TypeScript, Tailwind, and a static export build target.

## Quick start

```bash
cd app
npm install
npm run extract   # regenerates public/data/*.json from the source HTML
npm run dev       # http://localhost:3000
```

`npm run build` runs the extractor automatically before the Next.js build, so
edits to the source HTML report are always reflected in the static export.

## Layout

- `src/app/[therapy]/page.tsx` — server component, one route per therapy
  (`/hbot`, `/ir`, `/pemf`).
- `src/components/TherapyView.tsx` — client component. Renders each pane's
  HTML blob via `dangerouslySetInnerHTML`, rebuilds the show-more toggle,
  search filter, and Chart.js charts in React.
- `public/data/*.json` — generated by `extract/extract.mjs`. Each therapy
  payload contains its meta, tabs, chart configs, and one HTML string per
  pane (overview, all-ads, advertisers, hooks, longevity, strategy, scripts).

## Why HTML blobs instead of normalised data?

The source report inlines per-row styles heavily and several panes are
prose-rich (Hooks & Copy, OHR Strategy, Advertisers commentary). Re-rendering
those from structured data would be lossy. Embedding the original markup
preserves every visual detail; React only owns the layout shell, navigation,
filters, charts, and the show-more interaction.

## Static export

`next.config.mjs` sets `output: "export"`. After a build, the static site is
in `app/out/` and can be hosted anywhere.
